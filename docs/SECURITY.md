# Security Policy

## Supported versions

Only the latest release receives security fixes.

## Reporting a vulnerability

Do not open a public issue. Once maintainers enable private vulnerability reporting, use the repository's GitHub Security Advisory flow and include the affected version, reproduction, observed impact, and any useful logs or payloads. Until that remote control is enabled, contact a maintainer privately.

Never include credentials, private keys, personal data, or confidential project material. Maintainers will acknowledge practical reports and coordinate disclosure after a fix is available.
